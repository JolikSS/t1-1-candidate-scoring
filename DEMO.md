# Сценарий демонстрации

1. Настройте окружения, MongoDB, Neo4j и локальную E5 по `README.md`. В PyCharm выберите интерпретатор приложения.
2. Запустите `run_project.py` кнопкой Run. Дождитесь сообщения о готовности API и UI.
3. Откройте http://127.0.0.1:8501. Выберите сохранённую вакансию или загрузите ZIP с PDF/TXT-вакансиями.
4. Нажмите «Найти кандидатов»: расчёт использует сохранённые резюме MongoDB. ZIP резюме нужен только для добавления документов. Повторная загрузка тех же байтов не создаёт дубль.
5. Таблица показывает покрытие обязательных навыков, TF-IDF, семантическое сходство E5, RRF, найденные и недостающие навыки. Порядок: покрытие навыков по убыванию, затем RRF.
6. Для повторяемой проверки всех связей запустите `tools/verify_pipeline.py` при работающем приложении и доступных локальных архивах. Отчёт содержит агрегаты, без содержимого резюме.
7. Откройте Neo4j Browser http://127.0.0.1:7474 и посмотрите связи:

   ```cypher
   MATCH (run:ScoringRun)-[:FOR_VACANCY]->(vacancy:Vacancy)
   MATCH (run)-[:EVALUATES]->(resume:Resume)
   OPTIONAL MATCH (run)-[:OBSERVED]->(snapshot:SkillSnapshot)-[:OF_RESUME]->(resume)
   OPTIONAL MATCH (snapshot)-[:HAS_SKILL]->(skill:Skill)
   RETURN run, vacancy, resume, snapshot, skill
   LIMIT 50
   ```

8. Остановите сервисы запуском `stop_project.py`. Повторный запуск сохраняет документы и историю обеих баз.

Первый расчёт E5 дольше повторного. Косинус E5 и RRF не являются процентом пригодности; покрытие навыков не доказывает уровень владения. OCR сканов без текстового слоя не выполняется. Пользовательские ZIP, JSON, векторы и модели не входят в Git.
