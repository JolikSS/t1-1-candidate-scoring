# Продолжение PR39: извлечение требований вакансии

База: слитый PR39, main `660baf79ad6c73fcb16051381cf7f88fe5c7285a`.
Парсер: `vacancy-rules-2.4`, каталог: `professional-catalog-1.8` (479 названий).
Правила выражений: `expressions-1.4`.

## Поведение

- Требования распознаются в предложениях без заголовка: «Необходимо знание…»,
  «У вас есть опыт…», «Вы умеете…», «Наличие опыта…» и английские варианты.
  В смешанном разделе условий переносится только явное обращение к кандидату.
- Добавлены варианты заголовков требований и личных качеств. Сохранены границы
  компании, льгот, стека, обязанностей и контактов. Название заканчивается перед
  предложением о требуемых компетенциях; перенос составного названия сохраняется.
- Общий словарь дополнен профессиональными выражениями, вариантами написания
  и словоформами. Морфологический словарь pymorphy3 нормализует русские формы;
  simplemma остаётся для существующей подготовки TF-IDF и резервной нормализации.
- Сокращённые перечисления «гибридный и векторный поиск» дают обе компетенции.
  Версии Vue3, Java17, C++20 и т. п. сопоставляются с названиями технологий;
  исходные ограничения версии остаются в тексте. ROS и ROS2 остаются разными.
- В требованиях/пожеланиях возможен поиск неизвестных латинских названий и
  стандартов. В `parse_details.skill_candidates` сохраняется происхождение;
  `unregistered_skill_candidates` предупреждает о необходимости проверки.
  Такой кандидат ещё не является проверенным элементом общего словаря.
- Произвольный пользовательский каталог по умолчанию ограничивает поиск своим
  содержимым. `discover_unknown=False` включает строгий режим и для общего словаря.
- `discover_phrases=True` отдельно включает расширенный поиск русских именных
  групп по грамматическим правилам и техническим опорным словам. Форма головы
  и согласованных определений нормализуется; зависимые родительные сохраняются.
  Происхождение — `unregistered_phrase`, исходный фрагмент остаётся в диагностике.
  Этот режим выключен по умолчанию из-за более низкого precision.

Формулы TF-IDF, покрытия и итогового ранжирования не менялись. Общий модуль
сопоставления используется также для резюме; отдельная логика парсера резюме
не переписывалась. Существующие документы БД автоматически не переразбираются.
Нейросеть не обучалась: spaCy по-прежнему использует PhraseMatcher/Matcher
и общие правила, без загрузки языковой модели и без возврата E5.

## Измерение

Метрики PR39 сохранены. В странице проверки навыков добавлен переключатель
поиска новых технологий. Его изменение сбрасывает прежний результат.
JSON-отчёт содержит версию парсера, режим и SHA-256 исходных модулей.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-dev.txt -r requirements-skills.txt
.\.venv\Scripts\python.exe -m tools.evaluate_uploaded_skills "Требования JSON.zip" new_resume.zip -o reports/recall.json
```

Для строгого словаря: `--known-only`; для движка spaCy: `--backend spacy`;
для расширенного поиска русских выражений: `--phrases`.
В UI этому соответствует отдельный переключатель с предупреждением о precision.
Для UI: `streamlit run check_skills.py` из выбранного окружения.
Эталоны не извлекаются проверяемым парсером и не сокращаются до его словаря.

Диагностика на прежних 20 PDF, неизменных черновых эталонах и независимом
старом нормализаторе: 475 пар «вакансия + категория + понятие». Движок — regex.

| Версия | TP | FP | FN | Micro recall | Precision |
|---|---:|---:|---:|---:|---:|
| PR39 без этих изменений | 188 | 19 | 287 | 0,3958 | 0,9082 |
| Промежуточный вариант до продолжения | 256 | 53 | 219 | 0,5389 | 0,8285 |
| Текущий вариант по умолчанию | 269 | 67 | 206 | 0,5663 | 0,8006 |
| Расширенный поиск выражений | 285 | 108 | 190 | **0,6000** | 0,7252 |
| Текущий вариант, только словарь | 212 | 41 | 263 | 0,4463 | 0,8379 |

Это диагностический набор, **не подтверждённый независимый holdout**:
PR39 уже относит все исходные 55 PDF к development; черновую разметку двадцатки
нужно проверить вторым участником. Индивидуальные ошибки этих 20 документов
для написания новых правил не разбирались. Повторные измерения общей метрики
также не превращают этот набор в независимый тест.
При выборе вариантов неоднократно использовалась общая метрика двадцатки:
фактически она участвовала в выборе правил. Первоначальное обещание оставить
её только закрытым тестом не соблюдено; значение 0,6 не является независимой оценкой.

На пяти исходных вакансиях, в штатном измерителе PR39 по 190 группам обнаружения:
до — 157 TP / 5 FP / 33 FN, recall 0,8263, precision 0,9691;
после — 162 TP / 8 FP / 28 FN, recall 0,8526, precision 0,9529;
с расширенным поиском — 162 TP / 11 FP / 28 FN, recall 0,8526, precision 0,9364.
Эти пять документов использовались в разработке. Два измерения в этом разделе
имеют разные единицы и не должны сравниваться друг с другом как один ряд.

Локальные полные отчёты и воспроизводящий адаптер старых эталонов находятся в
`data/evaluation/recall_20261127/`: `baseline_reg20.json`, `final_default_reg20.json`,
`final_expanded_reg20.json`, `final_known_only_reg20.json`, `final_default_upload_dev5.json`,
`final_expanded_upload_dev5.json`, `evaluate_fixed.py`. Для адаптера двадцатки
нужно передать `reg20 --phrases --output НОВЫЙ_ОТЧЁТ.json`; старые отчёты не перезаписываются.
Архивы с исходными документами и персональными данными в Git не добавляются.

## Проверенные гипотезы и ограничение результата

Промежуточные варианты русских именных групп давали recall 0,587–0,589.
Добавление грамматических действий и неизвестных кириллических сокращений
не помогло; эти расширения не включены. Поиск строчных названий технологий
в явном русском контексте требований довёл расширенный режим до **0,6000**.

Порог достигнут **только на диагностическом наборе и в расширенном режиме**.
Независимое качество >= 0,6 не подтверждено. Рост recall сопровождается
снижением precision; его нельзя описывать как безусловное повышение качества.
F1 обычного режима — 0,6634, расширенного — 0,6567: больший recall не означает
лучший результат по всем метрикам. Для дальнейшего решения нужны новые документы с полной
разметкой, разделённые на development и закрытый тест, и согласованный предел
допустимого снижения precision. Обучение spaCy NER потребует разметки границ
упоминаний; одних списков названий в JSON для него недостаточно.
