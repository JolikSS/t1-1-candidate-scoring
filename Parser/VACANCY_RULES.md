# Правила навыков вакансии

Это контракт текущего парсера, а не оценка качества подбора на рабочем корпусе.
Извлечение разделов находится в `vacancy_parser.py`, классификация упоминаний —
в `vacancy_requirements.py`. Новых зависимостей нет.

## Разделы и результат

- `requirements`: обычные требования, `Must have`, обязательные требования.
- `preferred`: «Будет плюсом», «Желательно», `Nice to have` и другие варианты из
  `SECTION_ALIASES`. Общий механизм `document_structure.py` поддерживает также
  тире, завершающий вопросительный знак, нумерацию и PDF-маркеры списка.
- Обязанности, условия и сведения о компании не становятся источником
  обязательных или желательных навыков.
- Внутри требований без отдельного указания навык считается обязательным;
  внутри желательного раздела — желательным. Это явное допущение правил.
- `required_skills` содержит обязательные навыки, `preferred_skills` —
  желательные. Названия берутся из общего каталога с учётом существующих алиасов.
- `requirements` сохраняет текст раздела требований, включая отрицания и
  оговорки. `description` также сохраняет желательный раздел, обязанности и
  условия; неизвестные справочнику слова из текста не удаляются.

## Область действия формулировок

Классификация использует словарь регулярных выражений `QUALIFIERS`:
«обязателен», «будет плюсом», «не требуется» и их перечисленные варианты.
Эти правила не привязаны к отдельным технологиям.

Предложения, строки, точки с запятой и противопоставления ограничивают действие
формулировки. Точки внутри `.NET`, `Node.js` и версий не разделяют выражение.
Внутри одной части запятые и союзы «и» / `and`, «а также» / `as well as` образуют список:

| Текст требований | Обязательные | Желательные |
|---|---|---|
| Python обязателен; Docker желателен | Python | Docker |
| Python, SQL будут плюсом | — | Python, SQL |
| Python, желательно Docker | Python | Docker |
| Docker и SQL не требуются | — | — |

Маркер перед списком распространяется вперёд до следующего явного маркера.
Маркер после списка распространяется назад только на элементы, ещё не связанные
с предыдущим явным маркером. Между отдельными частями он не переносится.
Существующая проверка отрицательного опыта в общем поиске навыков сохраняется.

## Объяснения и противоречия

`parse_details.skill_evidence` содержит навык, статус (`required`, `preferred`,
`not_required` или `ambiguous`), исходный раздел, фрагмент очищенного текста,
контекст части предложения (`context`) и применённое правило. Контекст сохраняет
формулировку, распространяющуюся на весь список. Это объяснения распознанных
упоминаний, не исходный документ.

Обязательное упоминание имеет приоритет над желательным. Если навык одновременно
обязателен и явно не требуется, он исключается из обоих списков. В
`parse_details.warnings` добавляется `conflicting_skill_requirements:<навык>`.
Несовместимые маркеры в одном элементе тоже требуют проверки.

## Границы реализации и подключение

- Словари заголовков, навыков и формулировок конечны. Неизвестная формулировка
  может получить категорию раздела по умолчанию.
- Местоимения и пропущенные названия («Docker не требуется, но будет плюсом»),
  вложенные условия и сложные отрицания пока не разрешаются.
- Двусмысленные запятые обрабатываются по указанному правилу списков; оно может
  отличаться от авторского смысла. Неизвестные заголовки тоже могут нарушать границы.
- Известные ограничения общего поиска навыков, включая ложное `JS` внутри
  `Node.js`, остаются задачей отдельного блока нормализации.
- Новые поля доступны у `ParsedVacancy`. Их сохранение в MongoDB, экспорт через
  API и показ в UI ещё не подключены. Уточнённый `required_skills` уже передаётся
  существующим путём загрузки. Сохранённые вакансии сами не переразбираются.
- TF-IDF пока получает прежние поля: отдельного веса желательных навыков ещё нет.
- Правила выбора названия и границ разделов описаны в `DOCUMENT_STRUCTURE.md`.
- Примеры в `tests/test_vacancy_parser.py` и `tests/test_vacancy_requirements.py`
  запускаются через `python -m unittest discover -s tests -p "test_vacancy*.py" -v`
  в исправном окружении с pypdf. Реальные архивы и качество рейтинга ещё не проверены.
