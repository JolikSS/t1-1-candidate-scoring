# Должности и границы разделов

Общие правила находятся в `document_structure.py`. Их используют оба парсера.
Версии после изменения: резюме `rules-2.2`, вакансии `vacancy-rules-1.1`.
Словари навыков и формулы TF-IDF в этом блоке не меняются.

## Заголовки

Заголовком считается полное совпадение с вариантом из словаря или семейства
регулярных выражений. После него допускаются двоеточие, тире и содержимое либо
завершающая точка/вопросительный знак. Обычный текст после пробела сам по себе
не делает предложение заголовком.

Нормализуются пробелы, нумерация и распространённые PDF-маркеры списков.
Примеры: `1. Требования`, `● Условия: ...`, `Что нужно делать?`.
Вакансии также распознают семейства «Мы ждём от ...», «Наши ожидания ...» и
«Что мы предлагаем». Стек и описание текущей системы выделяются как контекст:
они сохраняются в описании, но не становятся обязательными навыками.

Для резюме отдельно предусмотрены длительность в заголовке опыта
(`Опыт работы 6 лет и 3 месяца`), «Обязанности и достижения»,
«Образование и обучение» / «Образование и самообучение». Название должности внутри истории работы остаётся
частью опыта и не подменяет желаемую должность.

## Выбор должности

Поиск ограничен первыми 40 строками и границами тела документа.
Приоритеты: явное поле должности, заголовок экспорта `Резюме: ...` /
`Вакансия: ...`, затем компактный блок строк с признаками профессии.
Для явного поля допускается значение на ближайшей следующей непустой строке.

В резюме навыки и краткое описание могут предшествовать желаемой должности;
опыт, образование и другие основные разделы прекращают поиск. После выбранной
должности данные о занятости не присоединяются к предшествующим навыкам.
В вакансии поиск прекращается при начале профессиональных разделов.

Неподписанные строки требуют слова из конечного словаря профессий/ролей.
Названия компаний, контакты, даты обновления и очевидная проза отбрасываются.
Зарплата в конце названия удаляется. Несколько равноправных разных вариантов
дают `ambiguous_title`, пустое поле и диагностические сведения, а не случайный выбор.
У вакансии для совместимости остаётся отображаемая заглушка «Вакансия».

Обрабатываются ограниченные случаи переноса названия: короткое продолжение
после запятой или известный термин после завершающего `/`. Для неразрешённого
окончания `/`, `,`, `(` добавляется `possible_wrapped_title`.

`parse_details.title_selection` содержит метод, количество вариантов и номер
исходной строки. Для вакансий строки предварительно освобождены от пустых;
для резюме номера соответствуют строкам извлечённого текста.
Если у резюме извлечена только должность, добавляется
`title_only_professional_text`: это не восстановленный опыт работы.

## Проверки и ограничения

Синтетические примеры и существующая обезличенная фикстура находятся в
`tests/test_document_structure.py`. Проверяется также исключение имён и контактов.
Команды для исправного Python-окружения с pypdf:

```powershell
python -m unittest discover -s tests -p "test_document_structure.py" -v
python -m unittest discover -s tests -p "test_vacancy*.py" -v
```

Локальные архивы и диагностические отчёты остаются вне Git. Сравниваются одинаковые
хеши архивов, ID документов и версии исходников. Заполненность поля не является
точностью извлечения: для её оценки требуется ручная разметка ожидаемых полей.
Бенчмарк ранжирования остаётся отдельной работой.

Не поддерживаются произвольные профессии без подписи, любые переносы строк,
таблицы и колонки с нарушенным порядком текста. Конечные словари не покрывают
все заголовки. Очистка личных данных остаётся эвристической.
Известные ограничения нормализации технологий, весов TF-IDF, E5 и сортировки
этим блоком не устраняются. Сохранённые записи MongoDB не переразбираются автоматически.
