# Сопоставление резюме с вакансиями

Учебный NLP-сервис: загружает PDF/TXT, ранжирует резюме под вакансию и показывает найденные и недостающие обязательные навыки. Сочетает TF-IDF, эмбеддинги multilingual-e5-base и объединение рейтингов RRF; результат доступен через FastAPI и Streamlit.

**Проверка 23 октября 2026: 23 из 23 модульных и компонентных тестов проходят.** Это проверка логики приложения, а не измерение качества найма: часть внешних компонентов в тестах подменяется.

**Стек:** Python · scikit-learn · E5 · FastAPI · Streamlit · MongoDB · Neo4j · Docker Compose.

## Мой вклад

Проект начинался как командный. Текущую версию развивал самостоятельно: обработка документов, ранжирование, интеграция баз данных, API и интерфейс.

## Как работает

```text
PDF/TXT → разбор и выделение навыков → MongoDB
                                  ↓
                 TF-IDF + E5 → RRF + покрытие навыков
                                  ↓
                   Neo4j → история → API → Streamlit
```

- **Лексический и смысловой поиск.** TF-IDF обучается на активном корпусе; готовая E5 ищет смысловые совпадения. Собственное обучение E5 не выполняется.
- **Объяснимый порядок.** Сначала покрытие обязательных навыков, затем RRF, затем стабильный ID. Найденные и недостающие навыки выводятся отдельно.
- **Повторная работа с корпусом.** SHA-256 исходного файла предотвращает повторное создание записи; эмбеддинги кешируются. Сохранённые резюме можно ранжировать без повторной загрузки.
- **История.** MongoDB хранит документы и результаты; Neo4j — связи, прогоны и снимки навыков. Старые прогоны не меняются при обновлении текущих данных.

## Проверить логику без запуска E5 и баз данных

Нужен Python 3.10+. Из корня репозитория, в отдельном окружении:

```bash
python -m pip install -r requirements.txt -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Тесты проверяют разбор документов и архивов, отрицания навыков, покрытие требований, TF-IDF/RRF, дедупликацию, кеш, обработку ошибок и интерфейс. Полный запуск настоящих MongoDB, E5 и Neo4j — отдельный сценарий ниже.

## Запустить приложение

Понадобятся Python 3.10+, Docker с Compose и место для модели E5. Альтернатива Docker на Windows — локальные MongoDB, Neo4j и Java 21, пути задаются в `.env`.

1. Установите зависимости приложения: `python -m pip install -r requirements.txt`.
2. Скопируйте [.env.example](.env.example) в `.env`; задайте собственный `NEO4J_PASSWORD` и параметры подключения к базам.
3. Создайте отдельное окружение E5: `python -m venv .venv-e5`. Установите в него [requirements-embeddings.txt](requirements-embeddings.txt), затем укажите путь к его Python в `EMBEDDING_PYTHON` внутри `.env`.
   - Windows: `.venv-e5\Scripts\python.exe -m pip install -r requirements-embeddings.txt`.
   - Linux/macOS: `.venv-e5/bin/python -m pip install -r requirements-embeddings.txt`.
4. Для начального корпуса положите свои `vacancies.zip` и `resumes.zip` в `data/` либо задайте `CANDIDATE_DATA_DIR`. В дальнейшем документы можно загружать через интерфейс.
5. Запустите `python run_project.py`. Скрипт запускает базы, API и интерфейс; UI доступен на **http://127.0.0.1:8501**, описание API — **http://127.0.0.1:8000/docs**.
6. Для остановки выполните `python stop_project.py`; данные баз сохраняются.

Модель: `intfloat/multilingual-e5-base`, revision `d128750597153bb5987e10b1c3493a34e5a4502a`. Для заранее скачанного снимка используйте `E5_MODEL_PATH`. Первый расчёт включает загрузку/кодирование и может быть существенно дольше повторного.

При запущенном приложении и подготовленных архивах полный сценарий проверяется командой:

```bash
python tools/verify_pipeline.py
```

Он проверяет реальные сервисы, повторную загрузку, кеш, согласованность графового порядка и истории. Этот сценарий изменяет локальный корпус и историю; для проверки используйте отдельные локальные данные.

## Границы результата

- Учебный прототип; релевантность ранжирования на размеченной выборке пока не измерена. Проходящие тесты не подтверждают качество отбора людей.
- Поддерживаются текстовые PDF и TXT. OCR для сканов нет; лимиты: 500 документов на пакет, 20 МБ на документ, 512 МБ на архив/распакованный пакет.
- Выделение навыков и очистка личных сведений эвристические. Используйте разрешённые для обработки документы; исходники, модели, векторы и `.env` храните вне Git.
- MongoDB и Neo4j не объединены общей транзакцией. При сбое история и граф могут потребовать проверки; ошибки E5/Neo4j не маскируются другим рейтингом.

<details>
<summary>Технические детали ранжирования</summary>

E5 получает `query:` и `passage:`; текст разбивается на фрагменты до 448 токенов с перекрытием 64. Используются нормализованные векторы и среднее лучших совпадений для фрагментов вакансии. Ключ кеша учитывает текст, префикс, revision модели и версию подготовки; повреждённый кеш пересчитывается.

RRF: `1/(60 + rank_tfidf) + 1/(60 + rank_e5)`. Покрытие обязательных навыков сохраняет приоритет, поскольку семантическая близость сама по себе не подтверждает наличие навыка.

</details>
