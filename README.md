# Система скоринга кандидатов

## Рабочий интерфейс

Запуск остаётся прежним: `run_project.py` кнопкой Run в PyCharm; остановка — `stop_project.py`.
Откройте `http://127.0.0.1:8501`. Используется Streamlit 1.49 и его системная тема; светлую/тёмную тему можно выбрать в меню Settings.

- **Вакансии:** поиск, просмотр требований и явное сохранение новой ручной вакансии. Каталог в новом UI доступен только для чтения; расчёт его не редактирует.
- **Резюме:** отдельная загрузка PDF/TXT/ZIP, поиск по роли/навыкам, карточки, выбор, скрытие и восстановление. Карточки показывают только роль, навыки, опыт и образование.
- **Рейтинг:** выбрать вакансию, затем весь активный набор, отмеченные резюме или документы последней загрузки текущей сессии. Скрытые документы исключены. Повторная загрузка возвращает прежние ID.
- **Результаты:** фильтры по кандидату, минимальному покрытию и TF-IDF, наличию всех выбранных навыков; смена сортировки, CSV текущей таблицы (UTF-8 BOM, разделитель `;`), сравнение 2–4 кандидатов.
- **История:** прошлые прогоны, снимки требований и профессиональных полей, сравнение двух завершённых прогонов одной вакансии. У старых прогонов отсутствующие снимки явно обозначаются.

Фильтры и выбор сохраняются при переходах между разделами. URL содержит раздел и ID вакансии; после обновления страницы UI восстанавливает текущую задачу и последний прогон, но несохранённые черновики, ручной выбор набора и сведения о последней загрузке относятся к сессии браузера.

Расчёт выполняется в фоне. Повтор одного запроса возвращает тот же прогон; для намеренного повторения используйте «Новый расчёт с тем же набором». Одновременно разрешён один расчёт. При аварийном перезапуске API незавершённый прогон получает статус ошибки; запускать повтор нужно явно. При штатной остановке API дожидается фонового исполнителя.

Скрытие не удаляет документы: повторный импорт сохраняет этот признак, восстановление возвращает запись в активный набор. История остаётся неизменной. Новые прогоны хранят снимки структурированных полей, поэтому объём базы растёт с количеством расчётов. Исходные файлы, имена файлов, хеши и полный очищенный текст в новом UI не отображаются. Анонимизация остаётся эвристической; проверяйте сведения перед использованием.

### API нового интерфейса

| Метод и путь | Назначение |
|---|---|
| `GET /workspace/stats` | Счётчики без загрузки полного корпуса. |
| `GET /workspace/vacancies` | Разрешённые поля вакансий. |
| `GET /workspace/resumes` | Краткий список с ID, ролью, навыками и видимостью. |
| `GET /workspace/resumes/{id}` | Структурированные профессиональные поля карточки. |
| `POST /workspace/uploads` | Multipart `files`; возвращает стабильные `resume_ids`, сведения о скрытых и ошибки элементов. |
| `PATCH /workspace/resumes/{id}` | JSON `{"hidden": true/false}`. |
| `POST /workspace/runs` | JSON `vacancy_id`, непустой `resume_ids`, `request_key`; HTTP 202. |
| `GET /workspace/runs/active` | Активный прогон либо `null`. |
| `GET /workspace/runs/{id}` | Статус, снимки и результат. |
| `GET /workspace/vacancies/{id}/runs` | История от новых прогонов к старым. |

Создание ручной вакансии использует прежний `POST /vacancies`. Старые endpoints сохранены, включая синхронный `/score`; он сохраняет прежнее поведение обновления вакансии и не используется новым UI. Локальный API запускается **одним процессом uvicorn**, без `--workers` и `--reload`: исполнитель и блокировка рассчитаны на один процесс, как в `run_project.py`.

## Что умеет приложение

- Импортировать `vacancies.zip` и `resumes.zip` при старте. В каждом ZIP поддерживаются PDF и TXT.
- Показывать импортированные вакансии в выпадающем списке и сразу рассчитывать рейтинг для всего набора резюме из MongoDB.
- Принимать дополнительные PDF/TXT/ZIP из интерфейса; распаковывать ZIP в памяти и добавлять документы к набору.
- Парсить текстовый слой PDF через `pypdf` и TXT с UTF‑8/Windows‑1251. OCR сканированных PDF не выполняется.
- Записывать в MongoDB только ID, формат документа, односторонний SHA‑256 для дедупликации и рабочие обезличенные поля: название/роль при наличии, навыки, опыт, образование, очищенный профессиональный текст. Имена, контакты, точные адреса, исходные имена файлов и полный сырой текст не сохраняются.
- Экспортировать обезличенные вакансии и резюме в `data/parsed_json/vacancies.json` и `data/parsed_json/resumes.json` для локальной проверки.
- Останавливать UI/API/MongoDB отдельным запуском `stop_project.py`; постоянный Docker volume при остановке сохраняется.

Архивы содержат персональные документы. Храните их локально, не добавляйте в Git и не используйте публичный сервер без отдельной оценки приватности.

## Скоринг

**Покрытие обязательных навыков, %** — количество найденных обязательных навыков, делённое на их общее количество. Поиск использует алиасы (например, `Postgres` → `PostgreSQL`) и ограниченные правила для простых отрицаний. Это понятная эвристика, не оценка уровня владения.

**TF‑IDF сходство, %** — косинусное сходство векторов вакансии и резюме. В отличие от прежнего расчёта на паре документов, IDF обучается заново на общем корпусе импортированных вакансий и резюме вместе с текущей вакансией. Заголовок и требуемые навыки имеют больший вес за счёт повторного включения в документ; опыт и требования также учитываются сильнее свободного текста. Используются слова и биграммы, подстрочные частоты и русско-/англо-/украиноязычный набор стоп-слов. Это лексическое сходство, оно не понимает смысл как языковая модель.

Метрики остаются отдельными: TF‑IDF не меняет Score по навыкам. Ни одна метрика не принимает решение о найме.

## Быстрый запуск из PyCharm

1. Откройте **этот клон репозитория** в PyCharm. На компьютере с заполненным диском C: разместите проект на диске с достаточным местом; Docker Desktop также должен иметь свободное хранилище.
2. Положите локальные `vacancies.zip` и `resumes.zip` в папку `data/`. В текущем рабочем окружении можно задать `CANDIDATE_DATA_DIR`, если архивы хранятся отдельно.
3. Лаунчер попробует запустить Docker Desktop, если он установлен. Если Docker Engine не поднимется, на Windows запустится локальная MongoDB 7.0.
4. Откройте `run_project.py` и нажмите зелёный **Run**. Скрипт проверит/установит Python-зависимости в выбранное окружение, поднимет MongoDB, импортирует ZIP и JSON, запустит FastAPI и Streamlit и откроет браузер.
5. Откройте `http://127.0.0.1:8501`, в разделе «Рейтинг» выберите вакансию и набор кандидатов, затем нажмите **Рассчитать рейтинг**. По умолчанию используются все активные резюме.
6. Для остановки запустите `stop_project.py` кнопкой **Run**. Не нажимайте Run у `run_project.py` второй раз, пока предыдущий экземпляр работает.

При Docker-запуске первый старт загружает образ `mongo:8.0`, поэтому нужен интернет. Windows fallback использует MongoDB Community 7.0, установленную вне клона; бинарники не попадают в Git.

### Среда Python

Лаунчер сначала использует `A:\CandidateScoringEnv\Scripts\python.exe`, если этот интерпретатор существует; иначе использует Python-интерпретатор проекта в PyCharm. Рекомендуется Python 3.10+. Зависимости перечислены в `requirements.txt`; ручной ввод команд не нужен.

## Данные и база

- MongoDB Community запускается контейнером `candidate-scoring-mongo`, база — `candidate_scoring`. Если Docker Desktop/WSL недоступен, Windows-лаунчер использует локальный MongoDB 7.0 из `A:\CandidateScoringData\mongodb\bin\mongod.exe`; данные этого режима хранятся в `A:\CandidateScoringData\mongo-data-native`.
- Порт `27017` опубликован только на `127.0.0.1`.
- Docker volume `mongo_data` переживает остановку контейнера и приложения. В локальном режиме каталог `mongo-data-native` сохраняется после остановки.
- Коллекции: `vacancies`, `resumes`, `scoring_runs`. В `resumes` действует уникальный индекс по SHA‑256 исходных байтов, чтобы повторный импорт/загрузка не создавала дубликат.
- Импорт повторяется при каждом запуске, идемпотентно обновляя вакансии и добавляя отсутствующие резюме. При изменении локальных документов для существующего хеша уже сохранённая запись остаётся прежней.
- Экспорт JSON — локальная копия обезличенных рабочих полей, исключающая исходный хеш и метаданные MongoDB.
- Папка `data/parsed_json`, оба ZIP и `.env` исключены из Git.

## REST API

- `GET /health` — состояние API и MongoDB.
- `GET /vacancies` — импортированные вакансии.
- `GET /resumes` — количество и обезличенные записи.
- `POST /vacancies` — создание/обновление вакансии JSON-объектом с `title`, `required_skills`, `description`.
- `POST /score` — пакетный расчёт; форма содержит `vacancy_title`, `vacancy_description`, `required_skills` (JSON-массив), `vacancy_id`, необязательные повторяемые `files`.
- `GET /vacancies/{vacancy_id}/results` — последний сохранённый прогон.
- `http://127.0.0.1:8000/docs` — Swagger UI.

Лимиты загрузки: 500 резюме в одном ZIP/пакете, не более 20 МБ на документ, 512 МБ на загрузку. В ZIP вложенные PDF/TXT обрабатываются отдельно; другие типы пропускаются.

## Ограничения и приватность

- OCR нет. Сканированные PDF без текстового слоя пропускаются.
- Анонимизация эвристическая. Она удаляет личную шапку до разделов профессионального опыта, простые строки с контактами, датами рождения, возрастом, адресом и семейным положением, email, ссылки и телефоны. Формат PDF может быть нестандартным, поэтому результаты нужно проверить перед использованием. Исходный документ нигде в приложении не сохраняется.
- Идентификатор кандидата случайный, имя из исходного файла не включается в интерфейс или записи. Повторная загрузка определяется SHA‑256, который хранится в локальной MongoDB для дедупликации, но не включается в JSON-экспорт.
- Все данные в этом варианте хранятся локально. Публикация данных резюме в GitHub запрещена настройками `.gitignore`; перед коммитом проверьте `git status`.
- Удаление Docker volume необратимо и для обычной остановки не требуется. `docker compose down -v` удалит импортированную базу.
