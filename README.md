# Parser: чтение и первичная обработка резюме

## Назначение

Ветка содержит модуль, который извлекает текст из машиночитаемых TXT и PDF, выделяет профессиональную информацию и находит упоминания навыков для последующего скоринга.

## Поддерживаемые форматы

- TXT: сначала UTF-8/UTF-8 с BOM, затем Windows-1251.
- PDF: текст извлекается библиотекой `pypdf`.
- ZIP обрабатывается сервером: его PDF- и TXT-файлы передаются парсеру по одному.

Зашифрованные PDF и документы без текстового слоя не читаются. OCR не реализован; сканированные изображения страниц не распознаются.

## Что извлекается

`parse_resume_bytes(file_name, content, skill_catalog)` работает с байтами файла в памяти и возвращает структуру `ParsedResume` с полями:

- `text` — очищенный текст документа;
- `name` — обнаруженное имя, если оно распознано;
- `professional_text` — содержимое разделов опыта и навыков для текстового сравнения;
- `skills` — совпадения из переданного каталога навыков.

При формировании `professional_text` парсер пропускает заголовки и разделы личной информации, образования и прочих нерелевантных сведений. В выбранном профессиональном тексте удаляются обнаруженные email, телефонные номера и URL. Поиск навыков использует каталог и правила из `scorer.skill_matching`.

## Ограничения приватности

Парсер может вернуть имя в объекте `ParsedResume`; сам по себе он не является полной системой обезличивания. В API исходное имя файла заменяется безопасным техническим именем, а в Neo4j сохраняются результаты и навыки, но не полное резюме. Перед распространением исходных файлов необходимо отдельно проверить, что в них не осталось персональных данных.

## Файлы ветки

- `Parser/resume_parser.py` — декодирование TXT/PDF, очистка текста, извлечение разделов и навыков, типизированные ошибки.
- `Parser/__init__.py` — публичные функции парсера.

Для полного сценария модулю нужны `scorer/skill_matching.py` и зависимости из `requirements.txt`; эти части находятся в соответствующих ветках проекта.
