# t1-1-candidate-scoring

Учебный MVP для сравнения резюме с требованиями вакансии.

## Запуск в Windows

В PyCharm выберите `run_project.py` в дереве проекта, нажмите правой кнопкой мыши и
выберите **Run 'run_project'**. Лаунчер использует готовое окружение
`A:\CandidateScoringEnv`, если оно доступно; иначе устанавливает зависимости в
интерпретатор PyCharm. Затем он запускает Neo4j через Docker Compose, API и UI,
дожидается их готовности и открывает `http://127.0.0.1:8501`.

Чтобы завершить API, UI и контейнер Neo4j с сохранением данных, нажмите **Ctrl+C**
в окне Run для `run_project.py` или запустите `stop_project.py` через **Run** в PyCharm.
Остановщик завершит также лаунчер, если он ещё работает.

## Парсер резюме

Поддерживаются машиночитаемые PDF и TXT, в том числе выгрузки резюме с hh.ru.
Скрейпинг сайта и OCR сканированных PDF не используются. Парсер получает список
обязательных навыков и отдельно выделяет текст из разделов опыта и навыков.
TF-IDF сравнивает этот текст с описанием вакансии; начальные строки резюме,
содержащие контакты и личные данные, в сравнение не входят.

Установить зависимость для чтения PDF:

```powershell
python -m pip install -r requirements.txt
```

Для проверки полного процесса используйте встроенный архив `data/workua_sample_70.zip`.
При запуске UI он загружается автоматически. Атрибуция и описание обработки находятся
в `data/WORKUA_SAMPLE_SOURCE.txt`.

## REST API и Neo4j

API построен на FastAPI, данные хранятся в Neo4j. В графе используются узлы
`Candidate`, `Resume`, `Skill` и `Vacancy`, связанные отношениями `HAS_RESUME`,
`HAS_SKILL`, `REQUIRES` и `SCORED_FOR`. При старте API создаёт ограничения
уникальности; вакансии добавляются вручную через интерфейс или `POST /vacancies`.

Для запуска Neo4j нужен установленный Docker Desktop. Создайте локальный файл
настроек и задайте свой пароль:

```powershell
Copy-Item .env.example .env
notepad .env
docker compose up -d neo4j
```

В `.env` замените значение `NEO4J_PASSWORD`. Этот файл игнорируется Git.
В новом окне PowerShell загрузите пароль из `.env` и запустите сервер:

```powershell
$env:NEO4J_URI = "bolt://localhost:7687"
$env:NEO4J_USERNAME = "neo4j"
$env:NEO4J_PASSWORD = (Get-Content .env | Select-String '^NEO4J_PASSWORD=').ToString().Substring(15)
python -m pip install -r requirements.txt
python -m uvicorn api.main:app --reload
```

Документация и интерактивная проверка API доступны по адресу
`http://127.0.0.1:8000/docs`. Основные endpoints: `GET /health`,
`GET /vacancies`, `POST /vacancies`, `POST /score` и
`GET /vacancies/{vacancy_id}/results`.
API рассчитан на локальную учебную демонстрацию и не имеет авторизации; не
публикуйте его в открытой сети.

## Веб-интерфейс

Запустите UI в отдельном окне PowerShell:

```powershell
python -m streamlit run ui/app.py
```

Интерфейс получает список вакансий из API или позволяет ввести вакансию вручную.
По умолчанию выбрана вакансия «Системный администратор» с набором навыков для
демонстрации. Описание вакансии необязательно: без него показывается Score по
навыкам, а TF-IDF остаётся пустым. Кнопка расчёта отправляет встроенный архив из
70 резюме; при необходимости можно добавить свои PDF/TXT/ZIP. Кандидаты сортируются
по покрытию обязательных навыков.

Каждый PDF или TXT внутри ZIP считается отдельным кандидатом; вложенные архивы
не распаковываются. Ограничения пакетной загрузки: до 100 файлов, до 20 МБ на
резюме и до 200 МБ общего распакованного объёма. Архив читается в памяти, а не
извлекается на диск.

В Neo4j сохраняются случайный псевдоним кандидата, тип файла, найденные навыки,
описание вакансии и обе метрики. Имя человека, исходное имя файла и текст
резюме не сохраняются; исходные имена файлов также не возвращаются интерфейсу.
В ZIP находятся переформатированные обезличенные записи Work.ua. Учитывайте
ограничения лицензии CC BY-NC 4.0 и описание набора в `data/WORKUA_SAMPLE_SOURCE.txt`.

## Текущая метрика

Score равен доле найденных обязательных навыков вакансии. Например, 3 найденных
навыка из 4 дают 75%. TF-IDF сходство рассчитывается отдельно по тексту опыта и
навыков и не влияет на Score. Для него нужно заполнить описание вакансии.
Ни одна метрика не является итоговой оценкой кандидата.

Для некоторых технологий поддерживаются явные варианты написания: например,
`JS` для JavaScript, `Postgres` для PostgreSQL и `Python 3` для Python. Простые
фразы вроде «не владею Python», «без опыта SQL» и «опыта с Docker нет» исключают
навык из совпадений. Это эвристики по ограниченному списку формулировок, а не
полноценное понимание контекста; спорные случаи нужно проверять вручную.

Сценарий демонстрации с ожидаемым результатом находится в `DEMO.md`.

## Тесты и локальный бенчмарк

```powershell
python -m unittest discover -s tests -v
python -m scorer.benchmark
```

Бенчмарк оценивает встроенный архив с теми же навыками по умолчанию, что и UI.
CLI также принимает путь к одному машиночитаемому резюме:

```powershell
python -m scorer.benchmark --resume путь\к\резюме.txt
```
